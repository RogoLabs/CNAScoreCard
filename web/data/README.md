# CNA Scorecard Data Structure Documentation

This document describes the JSON data files generated by the CNA Scorecard pipeline. All files are located in the `web/data/` directory and are automatically updated every 6 hours via GitHub Actions.

## Overview

| File | Purpose | Size | Update Frequency |
|------|---------|------|------------------|
| `cna_combined.json` | Complete CNA data with scores and metadata | ~380KB | Every 6 hours |
| `cna_list.json` | Official CNA registry data | ~393KB | Every 6 hours |
| `cna_summary.json` | Lightweight CNA rankings for leaderboard | ~100KB | Every 6 hours |
| `completeness_summary.json` | Analysis period metadata | ~100B | Every 6 hours |
| `field_utilization.json` | CVE field usage statistics | ~9KB | Every 6 hours |
| `performance_trends.json` | Daily scoring trends | ~75KB | Every 6 hours |
| `top_improvers.json` | CNAs with biggest score improvements | ~8KB | Every 6 hours |

---

## File Specifications

### cna_combined.json

**Purpose:** Complete dataset combining CNA scores with official CNA registry metadata. Used by CNA detail pages and full data exports.

**Format:** Array of CNA objects

**Schema:**
```json
{
  "shortName": "string",              // CNA short identifier (e.g., "Microsoft", "RedHat")
  "organizationName": "string",       // Full organization name
  "cnaType": "string",                // Primary CNA type (Vendor, Researcher, etc.)
  "cnaTypes": ["string"],             // Array of all CNA type classifications
  "rank": "number",                   // Current rank (1 = best)
  "active_cna_count": "number",       // Total number of active CNAs
  "percentile": "number",             // Percentile ranking (0-100)
  "total_cves": "number",             // Total CVEs published by CNA (all time)
  "recent_cves": "number",            // CVEs in analysis period (last 6 months)
  "is_active": "boolean",             // Whether CNA published CVEs in analysis period
  "scores": {
    "overall_average_score": "number",      // Aggregate score (0-100)
    "foundational_completeness": "number",  // Description, affected, references (0-100)
    "root_cause_analysis": "number",        // CWE coverage (0-100)
    "software_identification": "number",    // CPE coverage (0-100)
    "severity_and_impact": "number",        // CVSS metrics (0-100)
    "patchinfo": "number"                   // Patch reference coverage (0-100)
  },
  "trend": {
    "direction": "string",            // "improving", "declining", or "steady"
    "description": "string",          // Human-readable trend description
    "monthly_data": []                // Historical monthly scores
  },
  "scope": "string",                  // CNA scope description (may contain HTML links)
  "advisories": [{                    // Advisory publication locations
    "label": "string",
    "url": "string"
  }],
  "officialCnaID": "string",          // Official CNA identifier (e.g., "CNA-2017-0025")
  "country": "string",                // CNA headquarters country
  "disclosurePolicy": [{              // Vulnerability disclosure policy links
    "label": "string",
    "language": "string",
    "url": "string"
  }]
}
```

### cna_list.json

**Purpose:** Official CNA registry data synced from the CVE Program. Contains metadata for all registered CNAs regardless of activity status.

**Format:** Array of CNA objects

**Schema:**
```json
{
  "shortName": "string",              // CNA short identifier
  "organizationName": "string",       // Full organization name
  "scope": "string",                  // CNA scope description
  "cnaID": "string",                  // Official CNA identifier
  "type": ["string"],                 // CNA type classifications
  "advisories": [{
    "label": "string",
    "url": "string"
  }],
  "email": [{                         // Contact email addresses
    "label": "string",
    "emailAddr": "string"
  }],
  "country": "string",                // Headquarters country
  "disclosurePolicy": [{
    "label": "string",
    "language": "string",
    "url": "string"
  }],
  "rootCnaInfo": {                    // Parent Root CNA information (if applicable)
    "shortName": "string",
    "organizationName": "string"
  }
}
```

### cna_summary.json

**Purpose:** Lightweight summary data for the CNA leaderboard. Optimized for fast loading of the main rankings page.

**Format:** Array of CNA summary objects (sorted by rank)

**Schema:**
```json
{
  "cnaId": "string",                  // Official CNA identifier
  "shortName": "string",              // CNA short identifier
  "overallScore": "number",           // Overall score (0-100)
  "grade": "string",                  // Letter grade (A+, A, B, C, D, F)
  "previousPeriodCveCount": "number", // CVEs from previous analysis period
  "cveCount": "number",               // CVEs in current analysis period
  "type": "string",                   // Primary CNA type
  "trend": "string"                   // Trend direction indicator
}
```

**Grade Thresholds:**
- **A+**: 97-100%
- **A**: 90-96.99%
- **B**: 80-89.99%
- **C**: 70-79.99%
- **D**: 60-69.99%
- **F**: Below 60%

---

### completeness_summary.json

**Purpose:** Metadata about the completeness analysis run, including the analysis period and totals.

**Format:** Single object

**Schema:**
```json
{
  "analysis_period": "string",        // Date range (e.g., "2025-06-26 to 2025-12-26")
  "total_cves_analyzed": "number",    // Total CVEs in analysis period
  "total_fields_analyzed": "number"   // Number of CVE schema fields tracked
}
```

---

### field_utilization.json

**Purpose:** Statistics on how frequently each CVE schema field is populated across all analyzed CVE records. Used by the Record Completeness page.

**Format:** Array of field utilization objects (sorted by usage percentage)

**Schema:**
```json
{
  "field": "string",                  // Field path (e.g., "containers.cna.metrics")
  "percent": "number",                // Percentage of CVEs with this field (0-100)
  "unique_cnas": "number",            // Number of CNAs using this field
  "importance": "string",             // Field importance level: "High", "Medium", "Low"
  "description": "string",            // Human-readable field description
  "cna_scorecard_category": "string"  // Scoring category (null if not scored)
}
```

**Scored Categories:**
- `foundationalCompleteness` - Descriptions, affected products, references
- `rootCauseAnalysis` - CWE identifiers
- `severityAndImpact` - CVSS metrics
- `softwareIdentification` - CPE identifiers
- `patchInformation` - Patch URLs

---

### performance_trends.json

**Purpose:** Daily aggregated scores across all CNAs for trend visualization. Used by the Performance Trends page charts.

**Format:** Object with daily trend data

**Schema:**
```json
{
  "daily_trends": {
    "YYYY-MM-DD": {                    // Date key
      "root_cause_analysis": "number",       // Daily average (0-100)
      "severity_and_impact": "number",       // Daily average (0-100)
      "software_identification": "number",   // Daily average (0-100)
      "patch_information": "number",         // Daily average (0-100)
      "total_cves": "number"                 // CVEs published that day
    }
  }
}
```

**Notes:**
- Data spans the 6-month analysis period
- Daily averages are weighted by CVE volume
- Used for rolling 7-day trend calculations in the UI

---

### top_improvers.json

**Purpose:** Identifies CNAs that have shown the greatest score improvements over the analysis period. Featured on the Performance Trends page.

**Format:** Object with array of top improver CNAs

**Schema:**
```json
{
  "top_improvers": [{
    "cna_name": "string",             // CNA short name
    "total_improvement": "number",    // Sum of category improvements
    "category_improvements": {
      "root_cause_analysis": {
        "first_period": "number",     // Starting score (0-100)
        "last_period": "number",      // Ending score (0-100)
        "improvement": "number"       // Improvement delta
      },
      "severity_and_impact": { ... },
      "software_identification": { ... },
      "patch_information": { ... }
    },
    "total_cves_analyzed": "number",  // CVEs analyzed for this CNA
    "analysis_days": "number"         // Days of data analyzed
  }]
}
```

## Individual CNA Data Files

### web/data/cna/{shortName}.json

**Purpose:** Detailed data for individual CNA detail pages, including recent CVE list with per-CVE scores.

**Format:** Single CNA object with detailed CVE data

**Schema:**
```json
{
  "shortName": "string",
  "organizationName": "string",
  "scores": { ... },                  // Same as cna_combined.json
  "recent_cves": [{                   // Array of recent CVE details
    "cve_id": "string",               // CVE identifier (e.g., "CVE-2025-12345")
    "published": "string",            // ISO timestamp
    "description": "string",          // CVE description text
    "score": "number",                // Individual CVE score (0-100)
    "details": {                      // Per-category scoring breakdown
      "foundational": "number",
      "root_cause": "number",
      "software_id": "number",
      "severity": "number",
      "patch": "number"
    }
  }],
  "trend_data": { ... }               // Historical trend information
}
```

## Data Refresh Cycle

1. **Pipeline Execution**: Runs every 6 hours via GitHub Actions
2. **CVE Data Fetch**: Downloads latest CVE records from [CVEProject/cvelistV5](https://github.com/CVEProject/cvelistV5)
3. **Analysis Window**: Filters to most recent 6 months of data
4. **Score Calculation**: Applies Enhanced Aggregate Scoring (EAS) methodology
5. **File Generation**: Writes updated JSON files to `web/data/`
6. **Deployment**: Commits changes and deploys to GitHub Pages

## API Usage

These JSON files can be fetched directly for custom integrations:

```javascript
// Fetch CNA leaderboard
const response = await fetch('https://cnascorecard.org/data/cna_summary.json');
const cnaRankings = await response.json();

// Fetch specific CNA details
const cnaDetail = await fetch('https://cnascorecard.org/data/cna/Microsoft.json');
const microsoftData = await cnaDetail.json();
```

**CORS**: Files are served with appropriate headers for cross-origin requests.

**Rate Limiting**: No rate limits are currently enforced, but please be respectful of bandwidth.
